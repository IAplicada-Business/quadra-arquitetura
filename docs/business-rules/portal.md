# Business rules: client portal

Last verified: 2026-11-08, commit 4ad4101 (branch main) plus uncommitted working tree.

| ID | Rule | Where | Conditions, exceptions, tests |
|---|---|---|---|
| BR-093 | The portal is public at `/client/:token`. A token is valid when it exists, `is_active` is true and `expires_at` is empty or in the future. Otherwise the answer is 404 "Link inválido ou expirado" (same message for all causes). | `supabase/functions/get-client-portal-data/index.ts` | Tests: `src/test/clientPortal.test.tsx`, `src/test/useClientPortalToken.test.tsx`. |
| BR-094 | Only one active token per project. Rotating deactivates the active token and inserts a new one, in one RPC. | `supabase/migrations/20261106120000_portal_token_unique_active.sql` (`rotate_client_portal_token`, index `client_portal_tokens_one_active_per_project`), `src/hooks/useClientPortalToken.ts` | |
| BR-095 | The portal payload exposes only client-safe fields: tasks with `is_client_visible`, payments, invoices, up to 12 diary photos, up to 20 weekly reports, pending responses, activities, closing items, future visits (date and type only), quotes without supplier ids or `user_id`, scope items, purchases, onboarding. Internal notes are excluded. | `supabase/functions/get-client-portal-data/index.ts` | |
| BR-096 | A quote's discipline comes from its scope item. A quote without scope is shown under "Sem disciplina". `valid_until` and `note` are read in a separate query whose failure is ignored (columns may not exist yet). | `supabase/functions/get-client-portal-data/index.ts` | Temporary compatibility code. |
| BR-097 | Onboarding resolution: override with `is_enabled=false` shows nothing; override with `sections_json` list shows that custom copy; override with `template_id` shows that template live; otherwise the team's default template (found through the project owner's team). Failure returns `onboarding: null` and does not break the portal. | `supabase/functions/get-client-portal-data/index.ts`, `src/lib/onboarding.ts` (`onboardingMode`) | Tests: `src/test/onboarding.test.ts`, `src/test/onboardingTabs.test.tsx`, `src/test/onboardingEditor.test.tsx`. |
| BR-098 | Onboarding section layouts: `capa`, `card`, `texto`, `destaque`, `midia`. With no layout, the first section is a cover and the rest are cards. Placeholders in text are filled from project data. | `src/lib/onboarding.ts` (`sectionLayout`, `fillPlaceholders`, `buildOnboardingPlaceholders`) | Test: `src/test/onboarding.test.ts`. |
| BR-099 | Client answers to a pending item accept status `respondido`, `aprovado` or `rejeitado`. Required: `token`, `weekly_report_id`, `pending_item`, `status`. Token must be valid (403 otherwise). | `supabase/functions/submit-client-response/index.ts` | |
| BR-100 | Answers are idempotent per (`weekly_report_id`, `pending_item`): a repeat returns the stored answer with `duplicate: true`. A race is caught by the unique index (SQLSTATE `23505`). | `supabase/functions/submit-client-response/index.ts`, `supabase/migrations/20261104120000_*.sql` | |
| BR-101 | Every client answer creates a `client_response` notification for each admin. | `supabase/functions/submit-client-response/index.ts` | Only admins, not the project owner. |
| BR-102 | The portal refreshes silently: on a Realtime broadcast (`portal:<token>`, event `portal_changed`, debounced 300 ms), on tab focus, when the network returns, and every 15 s while visible. A failed refresh keeps the data on screen. | `src/hooks/useLivePortalData.ts` | A trigger on 14 tables sends the broadcast (`supabase/migrations/20261013210000_client_portal_live_updates.sql`). |
| BR-103 | The portal URL uses `VITE_PUBLIC_APP_URL` when set, else the current origin. A WhatsApp share link is built with a fixed Portuguese text. | `src/lib/portalUrl.ts` | Test: `src/test/portalUrl.test.ts`. |
| BR-104 | Portal tabs: `inicio`, `pendencias`, `galeria`, `orcamento`, `analise`, `prestacao`, `cronograma`, `compras`, `resumos`. The tab comes from the URL hash. | `src/lib/portal.ts` (`PORTAL_TABS`, `tabFromHash`) | Test: `src/test/portal.test.ts`. |
| BR-105 | Construction blocks: activities are grouped by discipline (else name, else "Outros"). Block state: `concluido` if all done; `em_andamento` if any done or running or start is today or earlier; else `a_iniciar`. Progress = average of activity progress (done counts 100). A block is late when not finished and its end is before today. Projects without activities fall back to `schedule_tasks`. | `src/lib/portalTrail.ts` (`constructionBlocks`, `trailActivities`) | Test: `src/test/portalTrail.test.ts`. |
| BR-106 | Project health has three signals. Deadline: risk if projected end passes the move-in date or 2 or more blocks are late; attention if 1 late. Decisions: open pendings plus overdue closing items; risk at 3 or more, attention at 1 or 2. Payments: late means `atrasado` or unpaid past due; risk at 2 or more, attention at 1. Labels: "No ritmo", "Atenção", "Em risco". | `src/lib/portalTrail.ts` (`projectHealth`, `HEALTH_LABEL`) | Test: `src/test/portalTrail.test.ts`. |
| BR-107 | Portal schedule rows show planned, elapsed, remaining and overdue business days using the reverse-schedule math (BR-047). | `src/lib/portalSchedule.ts` (`cronogramaReverso`, `resumoDoCronograma`) | Tests: `src/test/portalSchedule.test.ts`, `src/test/cronogramaTabelas.test.tsx`. |
| BR-108 | Purchase and contracting schedule is derived, not stored. Deadline to close = discipline start date minus supplier delivery lead time in business days. Lead time parsing: "N semanas" = 5N days, "N meses" = 21N, "N dias" = N (corridos converted by 5/7), a bare number = days, otherwise unknown (no date). Urgency: `fechado`, `atrasado` (negative), `esta_semana` (0 to 5 business days), `proximo`, `sem_data`. Already contracted disciplines are marked, not chased. | `src/lib/portalSchedule.ts` (`diasDeEntrega`, `recuaDiasUteis`, `linhasDeContratacao`, `linhasDeCompra`, `urgenciaDe`) | Test: `src/test/portalSchedule.test.ts`. |
| BR-109 | Budget scenarios are derived from current quotes: Econômico = lowest per discipline, Recomendado = approved quote else lowest, Máximo = highest. A contingency of 5% (`TAXA_IMPREVISTOS`) is added. Contracted amount is the sum of already contracted disciplines; to-contract = total minus contracted. Delta is relative to Econômico. | `src/lib/portalScenarios.ts` (`montaCenarios`, `TAXA_IMPREVISTOS`) | Test: `src/test/portalScenarios.test.ts`, `src/test/orcamentoAnaliseScreens.test.tsx`. |
| BR-110 | Valid proposals exclude non-current revisions, `rejeitado` quotes and placeholders. A placeholder has no value, or no supplier, or a supplier containing "prévia automática". Discipline names are trimmed and capitalized so "Marcenaria " and "Marcenaria" merge. | `src/lib/portalScenarios.ts` (`propostasValidas`, `ehPlaceholder`, `normalizaDisciplina`) | Test: `src/test/portalScenarios.test.ts`. |
| BR-111 | Validity badge per quote: `valida`, `vence_hoje`, `vencida`, `sem_prazo`. | `src/lib/portalScenarios.ts` (`validades`) | |
| BR-112 | Purchase stages for the client (`em_rota` is handled in code but is not in the `purchase_status` enum): `pendente` -> "decidir", `comprado` -> "pedido", `em_rota` -> "rota", `entregue` and `instalado` -> "entregue" (Na obra). Purchases group by category. | `src/lib/portalCompras.ts` (`etapaDaCompra`, `resumirCompras`) | Tests: `src/test/portalCompras.test.ts`, `src/test/comprasScreen.test.tsx`. |
| BR-113 | Adoption score = average of two ratios: answered decisions over total pendings, and closing items `comprado` or `entregue` over all closing items (only ratios with a non-zero total count; null if none). Upcoming deliveries come from move-in, closing dates, client dependencies, start, completion and visits. | `src/lib/portalTrail.ts` (`clientAdoption`, `upcomingDeliveries`, `journeyPosition`) | Test: `src/test/portalTrail.test.ts`, `src/test/inicioEtapas.test.tsx`. |
| BR-114 | The onboarding "seen" flag is stored per token in the browser. | `src/lib/portal.ts` (`onboardingSeenKey`) | |
| BR-159 | HTML analyses imported by staff (Orçamentos tab, "Importar análise (HTML)") are stored as-is in `budget_analysis_imports` (max 2 MB) and shown on the portal Análise tab in an iframe with an empty `sandbox` (no scripts). They never change `budget_quotes`. | `src/lib/analysisImport.ts`, `src/hooks/useBudgetAnalysisImports.ts`, `src/components/portal/screens/AnaliseScreen.tsx` | Test: `src/test/orcamentoAnaliseScreens.test.tsx`. |
